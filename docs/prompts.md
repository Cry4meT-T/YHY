## 第 0 轮：让 AI 先读懂任务书、拆分任务，不要急着写代码

**我的提示词（原文）**

```

帮我完成里面的考核并且将步骤一一解释给我 若有需要我主动进行的步骤请告知
```

**结果**：AI 先把 PDF 全文解析出来，逐条拆成清单，然后**反问我 4 个问题**（这一步很关键，避免它自作主张）：

| AI 的问题 | 我的回答 |
| --- | --- |
| 小游戏三选一，做哪个？ | 贪吃蛇 |
| 进阶挑战二选一，走哪条路？ | PySpice 三个电路 |
| 个人简介需要的真实信息（姓名/专业/联系方式/GitHub 用户名） | 我先发信息给你再开工 |
| 是否允许我自动装 Git/Python 等工具？ | 只给我步骤，我自己装 |

**为什么这样问效果好**：如果一上来就说「帮我做贪吃蛇」，AI 会直接开写，选题、环境、个人信息全都得返工。
先把**边界条件**问清楚（选题、环境权限、哪些必须我自己做），后面几乎不用回头改。

## 第 1 轮：贪吃蛇（阶段一 + 阶段二）

**我给 AI 的关键提示词（要点）**

```
先做风险最高的部分：单文件贪吃蛇（HTML/CSS/JS，双击能开，不许用框架）。
阶段一：方向键 + 触屏都能玩，要有得分、最高分、暂停、重开，界面干净。
阶段二：加 AI 自动操作，硬指标是「全程无人操作，连续吃 15 个食物不死」。
要求：AI 的核心逻辑必须能在 Node 里无头跑测试，我自己要验证 200 局，不能只靠肉眼看。
额外功能三个都做：计分制、主题切换、最近 10 局战绩。
```

**AI 的第一版设计**：纯贪心（每一步都朝食物最近的格子走）+ 「走完之后空格子还连通吗」的洪水填充检查。

**我追问（第 2 次迭代）**

```
贪心 + 连通性检查只是「大概率不死」，不是「保证不死」。给我一个数学上保证不死的兜底方案，
并且要能解释给面试的人听。
```

**AI 的调整**：
1. 先构造一条覆盖 20×20 全部格子的**哈密顿回路**（每个格子恰好经过一次、首尾相接）；
2. 蛇初始就沿着回路摆，**严格沿回路走 = 永远不可能撞到自己**（下一格要么是空的，要么正好是蛇尾刚离开的格子）；
3. 平时允许「抄近路」（走完仍然连通 + 离食物更近才走），长蛇阶段（超过棋盘 60%）**强制退回纯回路巡航**；
4. 用 BFS 距离场挑方向，保证步数单调下降，不会来回打转。

**第 3 次迭代（我要求加验证）**

```
写一个无头测试脚本，把 HTML 里的核心逻辑抽出来在 Node 跑，输出：回路合法性、
200 局连续吃 15 个的成功率、加压到 60/150 个的通过率、5 万步无食物巡航会不会死。
```

**测试结果（真实跑出来的）**

```
【回路校验】格子数 = 400；去重后 = 400；首尾相邻且每步位移为 1 = 通过 ✅
【阶段二硬指标】目标 = 连续吃 15 个食物不死 → 通过 200/200 局，失败 0 局
【加压测试】连续吃 60 个：通过 50/50 ✅ ；连续吃 150 个：通过 50/50 ✅
【生存测试】无食物干扰巡航 50000 步：存活 ✅
【极限测试】吃满整个棋盘（397 个食物）：通关 10/10 局
```

**第 4 次迭代（浏览器端真跑一遍）**

```
再用无头 Chrome 打开这个 HTML，检查：有没有 JS 报错、键盘/暂停是否生效、
开 AI 之后能不能真的自动吃到 15 个、主题切换刷新后是否保留、重置按钮是否生效，并截图。
```

**结果**：JS 报错 0 条；AI 自动吃到 15/15（HUD 显示「15 / 15」、状态「运行中（无需人工操作）」）；
主题刷新后保留；重置只清战绩、不影响当前这一局。截图见 `docs/game-ai-dark.png`、`docs/game-ai-light.png`。

## 第 2 轮：PySpice 三个电路

**我的提示词**

```
进阶挑战做 PySpice 那题。三个电路都要：RC 滤波（①）、戴维南验证（②）、
NMOS 共源放大（③，参数按题给固定）。每个都要：自己画的电路图、手算公式与过程、
PySpice 仿真波形、以及「理论值 vs 仿真值」对比表。脚本要能自己把表格和图片生成出来，
不要让我手动整理数据。
```

**迭代过程中遇到的问题（都是真实踩的坑）**

| 现象 | 原因 | 怎么改的提示词/代码 |
| --- | --- | --- |
| 脚本一跑就 `UnicodeEncodeError: 'gbk' codec can't encode 'µ'` | Windows 控制台是 GBK 编码 | 加 `sys.stdout.reconfigure(encoding="utf-8")`，并告诉我终端先 `chcp 65001` |
| 仿真值和手算差 1000 倍 | 我把已经是欧姆的数值又乘了一次 `u_kOhm`，1kΩ 变成了 1MΩ | 统一改成 `@ u_Ohm`，并在注释里写明 |
| 电流表读数是负的、短路电流只有 12µA | PySpice 分支名是设备名小写（`V('s')` → `vs`）；0V 电流表的符号约定搞反了 | 写了一个 `branch()` 兼容函数，正负号重新对 |
| 电压增益的直流分量把波形压成一条直线 | 输出骑在 V_DS≈3.29V 上 | 改成画「扣除直流后的交流分量」 |
| MOS 仿真电流只有理论值一半 | SPICE 的 MOS1 是 `I_D = ½·KP·(W/L)·Vov²`，题目给的 K 已经含 1/2 | 取 `KP = 2K = 1.6 mA/V²` |

| --- | --- | --- |
| ① τ / fc / 1kHz 增益 / 相移 | 100.0 µs / 1591.5 Hz / 0.8467 / −32.14° | 100.0 µs / 1584.9 Hz / 0.8467 / −32.14° |
| ② V_oc / I_sc / Rth / RL=500Ω | 6.0000 V / 12.0000 mA / 500.00 Ω / 3.0000 V | 完全相同 |

## 附录：我用来「查证 AI」的三个问题（原文与答案）

为了写 README 里「AI 给过但我查证后认为是错误的信息」那一节，我拿三个问题去问了 AI（不问上下文，独立回答），
然后**逐条自己核对**。原始问答如下（节选）：

### 问题 1：PySpice 的 NMOS 共源级直流工作点

> **AI 回答（节选）**：……所以取 KP = 2K = 1.6 mA/V²，W/L = 1……DC 解：V_G = 2V；假定饱和解 0.8(V_GS−1)²，
> **解得 V_GS = 1.7V，I_D = 0.392mA，V_out = 5 − 0.392m·2k = 4.216V**，饱和假设自洽。

**我的查证**：KP 的取值结论是对的（见第 2 轮的坑表），但后面这段工作点计算**是错的**。
栅极电流为 0，所以 V_GS 不是未知数，而是被分压电阻**钉死**在 2V：V_G = 5×40k/(60k+40k) = 2V。
如果真是 1.7V，就意味着 Rg1 上有 (5−1.7)/60k = 55µA 的电流，这与「MOS 栅极不取电流」直接矛盾。
正确结果：I_D = 0.8(2−1)² = 0.8mA（忽略 λ）、V_DS = 3.4V。详细过程写在 README 第 4.5 节。

### 问题 2：GitHub Pages 的仓库命名

> **AI 回答（节选）**：不需要命名为 `<用户名>.github.io`。仓库叫任意名字，Settings → Pages →
> Deploy from a branch → main + /(root)，网址就是 `https://<用户名>.github.io/<仓库名>/`。

**我的查证**：结论与 GitHub 官方文档一致（项目站点用任意仓库名 + 子路径；
只有想要根路径 `https://<用户名>.github.io/` 时才必须把仓库命名为 `<用户名>.github.io`）。
所以我按「任意仓库名」这条路走。

### 问题 3：哈密顿回路为什么能保证贪吃蛇不死

> **AI 回答（节选）**：哈密顿回路给每个格子唯一序号……蛇头前进一格序号 +1，该格要么为空、
> 要么恰是蛇尾，而尾巴这一步会移走，所以永不自杀（前提：初始蛇身按回路连续摆放）。
> 抄近路时的安全条件：移动后仍能从新蛇头到达蛇尾，且可达区域 ≥ 蛇长。

**我的查证**：与我自己写的实现思路一致，我进一步改成了「移动后所有空格子仍然连通」这个更强的条件，
并写了 5 万步生存测试来实测验证（见第 1 轮）。
